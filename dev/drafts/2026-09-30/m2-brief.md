# M2 の依頼書：機器台帳・ペアリング管理・機器ごとの機能（画面なし）

別のセッション（クラウドの Claude など）に M2 を作ってもらうための依頼書。M1 の依頼書 [m1-brief.md](../2026-09-27/m1-brief.md) と同じ形。設計は [implementation-design.md](../2026-09-27/implementation-design.md)、決定は [requirements.md](../2026-09-26/requirements.md) の F1〜F5、G、I4・I5・I7 と、2026-09-30 の J1〜J3。会話は日本語、平易な表現で、結論を先に。事実と推測を分け、確かめていないことは「未確認」と書く。

## 1. 目的と範囲

**目的**：M1 で「本家と同じ」になった M5Dial に、Orbit の芯を足す。機器を安定した番号で覚え、ペアリングを本体で管理し、機器ごとにレイヤーを持ち、切断したら押しっぱなしを解除し、設定セットを切り替え、LED を送り返す。**画面は作らない**（M3）。操作は本体のボタンとシリアル（ログの CDC）で行い、画面に出す情報と操作の型だけを決める（決定 I7）。

**3 段階に分け、1 段階 = 1 PR 以上、段階ごとに `.bin` を渡して実機で確かめてから次へ進む**（M1 と同じ運び方）。

| 段階 | 中身 | 本家コアの改造 |
| --- | --- | --- |
| 2a | 機器台帳（安定したポート番号、名前、付け替え）、ペアリング管理（1 台削除、上限、組み直しの許可 G-1〜G-4）、設定ツールへの Orbit の命令 | なし |
| 2b | 機器ごとのレイヤー（F2-2、F2-3、F2-4）、切断時の解除（F2-5） | **あり**（最小のパッチ、`// ORBIT:`） |
| 2c | 設定セット（F3-4、決定 I5）、LED の送り返し（F5-1） | なし |

**この段階でやらないこと**：画面（LVGL、M3）、グラフィカルな設定ツール（要件 F。別リポジトリ、M2 の命令が固まってから）、アドレスが変わる機器（RPA）の確認（要件 D の前半。該当機器が無い。2a の試験に項目だけ入れる）、Orbit の VID/PID（Q35）、段階 3 の探索の省略（[ble-connect-plan.md](../2026-09-28/ble-connect-plan.md)）。

## 3. 段階 2a：機器台帳とペアリング管理

### 3.1 台帳（決定 I4）

- 1 行 = 1 台。鍵は **アドレス＋種類**（Q37。同じアドレスの 2 台は規格外なので対応しない）。
- 列：ポート番号（1〜15、永続）、表示名、別名（利用者が付ける。空でよい）、種類、VID/PID（PnP ID。無い機器は 0）、記述子の要約（M1 の `hash=`、FNV-1a 32 ビット）、名前・製造者・型番（M1 の `info`）、最後に使った時刻（起動からの秒ではなく、起動回数か単調増加の番号でよい。時計が無い）。
- 保存先：NVS の名前空間 `orbit`（設定と同じ）。NimBLE のペアリング情報（`nimble_bond`）とは別に持ち、起動時に突き合わせる。**ペアリング情報があって台帳に無い機器は、台帳に足す**（M1 からの移行。番号はペアリング情報の並び順で振る）。**台帳にあってペアリング情報が無い機器は、行を残して「鍵なし」と印を付ける**（利用者が消すか、G の組み直しで戻る）。
- **ポート番号**：ペアリングしたときに空いている最小の番号を振り、以後変えない。`device_connected_callback()` の `hub_port` にこの番号を渡す（今の `bond_index()` を置き換える）。本家の設定ツールからは「ポート番号」としてそのまま見える（F1-4）。
- **表示名の決め方**（要件 B）：別名 → 機器の名前（GAP Device Name。前後の空白は削る） → 製造者＋型番 → 種類＋アドレスの下位 2 バイト（例 `mouse ..:21:96`）。同じ表示名が 2 行あれば `#1`、`#2` を付ける（J3）。
- **種類**：記述子の要約から判定する（キーボード、マウス、ゲームパッド、その他。本家の `descriptor_parser` が出す usage の集合で判定）。外観（Appearance）は補助（機器 B は `0x0080` を返した）。
- **付け替え**（決定 4 の C）：「この行（新しい機器）を、以前の番号 N と同じ扱いにする」命令。新しい行が N を引き継ぎ、古い行は消える。別名も引き継ぐ。
- **同じ機器らしい古い記録の自動の置き換え**（要件 D の後半、J3）：ペアリングで新しい機器が来たとき、VID/PID と記述子の要約が一致する行を探す。VID/PID が無い機器は「名前＋製造者＋型番＋記述子の要約」で代用。**候補が 1 行だけで、その 1 台が今つながっていないときだけ**、自動で付け替える（ログに `replaced port N` を出す）。候補が 2 行以上、または候補がつながっているときは、新しい行として足し、`同じ機器らしい記録が複数`（画面に出す状態）を立てる。自動では消さない。

### 3.2 ペアリング管理（F3-3、G、J1）

- 上限：`CONFIG_BT_NIMBLE_MAX_BONDS=15`、`CONFIG_BT_NIMBLE_WHITELIST_SIZE=15`。根拠は本家のポート番号（4 ビット、1〜15）と S3 の許可リストの上限 15。保存領域は上限にならない（1 台約 16 件、区画 4,032 件）。**要確認**：許可リストに 15 台渡した待ち受けが今までどおり動くか（今は 2 台）。
- **いっぱいのとき**：ペアリングを始めずに `bonds full` の状態を立て、ログに出す。利用者が 1 台消す。自動では消さない（本家と各 OS は黙って消すか黙って失敗するが、Orbit は画面で選ばせる。[ble-limits-prior-art.md](ble-limits-prior-art.md) §5）。ただし 3.1 の自動の置き換えは「更新」なので、いっぱいでも行う。
- **1 台削除**：台帳の行とペアリング情報（`ble_store_util_delete_peer()`）の両方を消す。つながっていれば切る。本家の `clear_bonds`（全削除）は残す。
- **組み直しの許可（G-1〜G-4）**：通常時に登録済みの機器が組み直しを求めたら（鍵が無い `0x0506`、自分からペアリングを始めた、保存した鍵に答えない）、今は切って 30 秒外す。M2 では：
  - G-1：`approval wanted` の状態を立てる（どの行か、理由、残り時間）。ログと画面の状態の写しに出す。
  - G-2：ボタンの短い押し込み（1 秒未満で離す。M1 の 2 秒の押し込みは Pair new device のまま）で、**その行のアドレスに限って** 60 秒、組み直しを受け付ける。受け付けたら新しい鍵で台帳の同じ行を使う（番号は変わらない）。押さなければ今までどおり切って外す。
  - G-3：暗号化されるまで入力を PC に渡さない（今の作りで満たす。通知の登録は暗号化の後）。設計に明記する。
  - G-4：同じ行を 3 回断ったら、再起動まで `approval wanted` を立てない。
- **Pair new device の終わり方**：今は 1 台つながると終わる。M2 でも同じ。加えて **2 分たったら自動でやめる**（本家は永久に待つが、置き忘れると誰でもつなげる状態が続く。J1 と同じ「安全側」）。ボタンの 2 秒でもやめられる（M1 のまま）。

### 3.3 設定ツールへの Orbit の命令

- 本家の設定用 HID（HID 1、feature report）に Orbit の命令を足す。番号は **0x80 以上**（本家は 1〜21。将来本家が足しても衝突しない）。本家の命令と設定の形式は変えない（決定 5。本家のツールはそのまま使える）。
- 命令：台帳の読み出し（行ごと。ページング）、別名の書き込み、1 台削除、付け替え、ペアリング開始（本家の 12 で足りる）、設定セットの一覧・選択（2c）。
- 応答の形は、要件 F のツールがそのまま使えるように、この段階で決めて README に書く。文字列は UTF-8、最大 32 バイト。

### 3.4 状態の写しと命令の型（決定 I7）

M3 の画面はこれだけを使う。M2 では同じ内容をシリアルに出す（1 秒ごとの `SUM`／`DEV` 行に足すか、新しい `ORB` 行）。

- **状態の写し**：台帳の各行（番号、表示名、つながっているか、鍵の有無、今のレイヤー、実際の接続間隔）、ペアリング待ちか（残り時間）、`bonds full`、`approval wanted`（行、理由、残り時間）、`同じ機器らしい記録が複数`、今の設定セット、直近のできごと。
- **命令**：Pair new device 開始・中止、組み直しの許可、1 台削除、付け替え、別名（設定ツールから）、レイヤー切替（2b）、設定セット切替（2c）。
- M2 の操作手段：ボタン（2 秒＝Pair new device、短い押し込み＝組み直しの許可）と、**シリアルの 1 行命令**（CDC に `orbit forget 3` のように打つ。試験用。M3 で画面に置き換える）。

## 4. 段階 2b：機器ごとのレイヤーと切断時の解除（本家コアの改造）

- **F2-2**：`layer_state_mask` を本体に 1 つから **ポート番号ごと** にする（0 番＝全機器向けの設定は、入力が来たポートのレイヤーで評価する）。改造は `remapper.cc` の `process_mapping()` 周辺に限り、`// ORBIT:` の印。本家の更新を取り込みやすいよう、差分を 1 つのパッチとして `firmware/hid-remapper/UPSTREAM.md` に列挙する。
- **F2-3**：機器のレイヤーキーは押した機器のポートに効く。ボタン・ダイヤルからの切替は、命令「ポート N をレイヤー L に」で行う（M2 ではシリアルから）。
- **F2-4**：ある機器のキーで別の機器のレイヤーを切り替える。本家の設定の「出力先のポート番号」（`hub_ports` の上位 4 ビット）で指定できるかを**先に確かめる**（未検証）。できなければ、Orbit の命令で代用し、その旨を書く。
- **F2-5**：機器が切れたら、その機器の押下状態だけを解除する。本家の `input_state` はポート番号込みの鍵で持つので、`device_disconnected_callback()` でそのポートの状態を 0 にして `process_mapping()` を 1 回通せば、解放の報告が出る見込み（推測）。**先に確かめること**：本家が切断時に押下状態を解除しているか（requirements F2-5 は「見当たらない」）。他の機器の入力とレイヤーは維持する。
- 改造の前に、M1 の合格条件 A2・A7・A8 を改造後にもう一度通す（回帰）。

## 5. 段階 2c：設定セットと LED

- **設定セット（F3-4、決定 I5）**：本家形式の塊（2,048 B）× N ＋ Orbit のヘッダー（版、今のセット番号、各セットの名前）を NVS に保存。本家の `do_persist_config()` と起動時の読み込みは、**今のセット**に対して行う。PC のツールは無改造で、本体で選んだセットを編集する。保存できる数は実測して決める（Q34。NVS の残りは 3,700 件超なので 8 セットで約 550 件。推測）。切り替えは Orbit の命令（M2 ではシリアル、M3 で画面）。切り替えたら `set_mapping_from_config()` を呼び直し、押下状態は全部解除する。
- **LED の送り返し（F5-1）**：本家コアの `queue_out_report()` を実装する。PC からの出力レポート（CapsLock などの LED）を、HID の Output Report（Report Reference の type = output）を持つ機器に **GATT の書き込み（Write Without Response）** で送る。探索のときに出力レポートのハンドルも記録する（今は入力だけ）。本家 BLE 版は未実装（`// TODO`）なので手本は無い。**要確認**：手持ちの機器で Output Report を持つもの（MD600、meteorite40 が候補。IST と 機器 B は持たない見込み）。

## 7. 渡すもの

M1 と同じ：ブランチ（最新の `main` から。名前は作業に合わせる）、1 テーマ 1 コミット、各コミット単独でビルド、author は `techmech <88352328+techmech-keeb@users.noreply.github.com>`、PR は作るがマージは利用者が判断する。`.bin` はリポジトリに入れず利用者に直接渡す（名前に `git describe`、SHA-256 を添える）。README に台帳・命令・シリアルの 1 行命令・状態の写しの形を書く。結果の報告は §6 の表を埋める。

## 8. 守ること

M1 の §7 に加えて：

- 本家コアの改造は 2b だけ。差分は 1 つのパッチとして列挙し、本家の更新を取り込むときの手順を `UPSTREAM.md` に書く。
- 台帳とペアリング情報の整合が崩れても起動できること（片方だけある行は消さずに印を付ける）。
- 台帳の名前は機器の製品情報なのでログに出してよい。アドレスは下位 2 バイトだけ、鍵は出さない。
- 通常時に誰でもつなげる状態を作らない（組み直しの許可はアドレス限定・60 秒、Pair new device は 2 分）。

## 9. 決めてよいこと・聞いてほしいこと

- **決めてよい**：台帳の NVS の鍵の形、Orbit の命令番号の割り当て（0x80 以上）、シリアルの 1 行命令の文法、種類の判定の細かい規則、`ORB` 行の書式。
- **聞いてほしい**：2b で改造が `process_mapping()` の外に広がるとき／F2-4 が本家の「出力先のポート番号」で実現できないと分かったとき／設定セットが 4 つも入らないとき／Output Report を持つ機器が手持ちに無いとき／許可リスト 15 台の待ち受けが動かないとき。
