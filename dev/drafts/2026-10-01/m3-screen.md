# M3 画面：2 日で作る範囲と試験

## 2. 作り（事実）

- `main/ui.c`：LVGL のタスクは CPU0・優先度 2（NimBLE のホストより下、主ループは CPU1）。描画バッファは 240×30 px × 2 枚（約 29 KB、DMA）。M1 から確保していた 48 KB をこれに充てる（決定 I3）。LVGL のメモリは自前のプールではなく通常のヒープ（`CONFIG_LV_USE_CLIB_MALLOC`）。
- 状態は 1 秒ごとに `status_task` が `orbit_ui_state_t` にまとめて渡す（`ble.h`・`ledger.h` の既存の関数だけ）。命令は `orbit_ble_*` を呼ぶ。
- ダイヤルは PCNT（G40／G41、M5Dial の資料どおり）。1 クリック＝4 エッジと仮定（**要確認**：逆や倍速なら `ENC_STEPS_PER_DETENT` と向きを直す）。
- ボタンの短い押し込みは主ループから旗を立てるだけ（主ループは待たない）。LVGL のタイマー（50 ms）が旗を読む。
- 書き込みモードに入るときは全画面の通知を出し、LVGL のロックを持ったまま再起動する。起動時にボタンを押していた場合は、LVGL の前なので従来の文字画面。
- 元の文字画面（`display.c`）は残し、LVGL が始められなかったときだけ使う（`START` 行の `lvgl_reserve=lvgl/text`）。

## 3. 試験（ローカルのセッション、版 `9c63777`）

接続の処理は PR #27 の `4903ae1` と同じ。**先に `4903ae1` の試験を終えてから**この版を書き込む（この版は `4903ae1` の上に積んである）。

1. 書き込み → 画面が LVGL の画面になること（リング、カード 2 枚、状態行、下の数字）。`START` 行の `lvgl_reserve=lvgl`。起動から画面が出るまでの秒数。
2. 2 台つながる → リングが緑、カードに名前（`IST TrackBall`、`(略)`）、`P1`／`P2`、`7.50 ms`、1 秒の報告数が入力で増えること。カード左の点が、入力中は緑、入力なしは青。
3. ダイヤルを回す → カードの枠が青く光る順に移ること（上 → 下 → なし → 上）。**向きと 1 クリックの刻み**を報告（1 クリックで 1 つ動くか、2 つ飛ぶか、逆か）。
4. 押し込み → メニューが出る。回して `Close` → 押し込みで閉じる。
5. メニューの `Pair new device` → リングが黄、状態行に残り秒。もう一度メニュー → `Stop pairing` → 元の色に戻る（2 台つながっていれば緑、待ち受けなら青）。
6. `Forget port 2` を選んで押す → `Really forget?` に変わる → もう一度押す → 機器 B が切れ、カードが `--`。メニューの `Pair new device` → 機器 B をペアリングし直し → カードに戻る。
7. 承認の問いは MD600 があるときだけ（B6 の手順）。
8. 書き込みモード（1200 bps）→ 画面に `DOWNLOAD MODE`。
9. **5 分の使用**で切断 0、`LAT` の基準（3 ms 超の秒が 1 分に 1 回以下、5 ms 以内）、`heap_min` を写す（2a の 87 KB からの差）。画面の描画が入力の遅れに出ていないかが一番の確認点。
10. 気づいたこと：読みにくい文字、はみ出し、色の意味の分かりにくさ、欲しい情報・操作。2 日目の直しに使う。

ログは `M1 EVT ... screen: ...` の行でメニューの操作を残す。

## 4. 2 日目の版 `015df03` の試験

`orbit-m3-015df03-ble.bin`、SHA-256 `829dfa84636747432a357cd45758424ab6576e9b94c28baa233ee6e9ab92d330`。`9c63777` との違いは描画の仕方と、メニューの `Rotate` と `Screen off`。接続の処理は `main` の 2a（`4903ae1`）と同じ。

1. 書き込み → 画面が出ること。`screen: lvgl rotation=0 screen_off=never` の行。
2. **5 分の使用**（一番の確認点）：切断 0、`LAT` の基準（3 ms 超の秒が 1 分に 1 回以下、5 ms 以内）、状態の行の間隔（9c63777 は 1.12 秒、画面なしは 1.03 秒）、`heap_min`。
3. メニューの `Rotate: 0 deg` を押すたびに 90° ずつ回ること（文字が鏡にならないこと）。RST 後も向きが残ること。`Rotate` を 4 回押して 0° に戻す。
4. メニューの `Screen off: never` を押して `30 s` にする → 30 秒ほど触らないと画面が消えること → ダイヤルかボタンを 1 回触ると点くだけで何も起きないこと（2 回目から操作）。消えている間にシリアルから `orbit pair` を打つと画面が点くこと。`Screen off` を `never` に戻す。
5. `Pair new device` の残り秒が見切れないこと（状態行は円の内側 184 px、長ければ末尾が `…`）。
6. 1 日目の手順 3〜6（ダイヤル、メニュー、Forget、ペアリングし直し）が変わらず動くこと。
7. 気づいたこと（読みにくさ、はみ出し、欲しいもの）。

1 日目の報告の 3（画面から押したときに 機器 B が見つかるまで 12 秒）は今回は触っていない。探索の割合（10/100 ms）はつながっている機器の入力を守るために下げたもので、上げると IST の `rpt=` が落ちる。「探索中」の表示は状態行の `Pairing 118s: turn on a device` が兼ねる。急がないので、後で「つながっている機器が無いときは 30/60 に戻す」を検討する。

## 6. `bd6895d`：e72c27a の報告への対応

`orbit-m3-bd6895d-ble.bin`、SHA-256 `8419e5274f54d917233b148076022f2d1d0c46039ce271519a8667974137e4f3`。[報告](../2026-09-27/reports/m3-e72c27a-report.md)の 4 点の直しは合格。残りの 3 点：

| 報告 | 対応 |
| --- | --- |
| 1. IST と MD600 を同時に大きく使うと 3 ms 超が増える（最大 3.84 ms） | **画面のせいではないと見る**（向きを変えても同じ、保存・命令・接続のない秒、状態の行の間隔は 1.006 秒）。まず切り分け：**画面の無い `4903ae1` で同じ使い方（IST を 100/s 以上、MD600 を同時）を 3 分**測る。同じなら、受け取りから USB までの経路（1 ms の刻み、USB の 1 ms のフレーム、2 台分の報告の処理）の限界で、基準を「2 台とも 7.5 ms で同時に大きく使うときは 4 ms 以内」と分ける案。この版では手を入れていない |
| 2. 機器に古い鍵が残っていると 0.5 秒おきにつなぎ直す | 直した：Orbit に鍵が無いのに「保存した鍵が通らなかった → ペアリングし直し」の経路に入っていた。`rc=0x6` は、失敗した手続きが NimBLE の 1 つしかない SM の枠をまだ占めているため。鍵が無いときは `device refused to pair: it still holds an old key for Orbit; clear Orbit on the device` を出して切り、2 回で 30 秒外す。鍵があるときの `rc=0x6` は periodic_check から再試行 |
| 3. 180° で下の行の末尾が縁にかかる | 下の行を 140 px・縁から 30 px に |

試験（利用者の希望で **180°** で）：
1. 180° で下の行が欠けないこと。
2. 2 の再現：MD600 に Orbit の鍵を残したまま `orbit forget 3` → `orbit pair` → MD600 の電源を入れ直す → `device refused to pair ... clear Orbit on the device` が出て、つなぎ直しが 2 回で止まり 30 秒外されること（`ignoring the device for 30 s`）。MD600 を再起動してペアリングモードにすると新しいアドレスでつながること。
3. 切り分け：`4903ae1`（画面なし）で IST と MD600 を同時に 3 分 → 3 ms 超の秒の数。次にこの版で同じ使い方を 3 分。
