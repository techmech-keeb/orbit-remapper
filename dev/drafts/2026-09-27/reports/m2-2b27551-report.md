## 直してほしいこと

### 1. 「入力が止まってから書く」が働いていない（不具合）

- `main.cc` の主ループは `orbit_ledger_flush(false, lat_last_rx_us)` を呼び、`ledger.c` は `now - last_input_us < LEDGER_FLUSH_IDLE_US` なら書くのを待つ。
- ところが `lat_last_rx_us` は `LAT` を測るための変数で、`orbit_report_sent()` が入力を PC に送り終えるたびに **0 に戻す**。主ループが `orbit_ledger_flush()` を呼ぶのは送り終えた後なので、ほとんどいつも 0 を渡すことになる。
- 0 を渡すと `now - 0` は 1 秒より大きいので「入力は止まっている」と判断され、入力の最中でもすぐ書く。今回の 12 回の保存が、どれも変更の直後だったのはこのため。
- 案：`LAT` の変数とは別に、`lat_note_received()` で「最後に入力が来た時刻」を 0 に戻さずに持つ変数を用意し、それを `orbit_ledger_flush()` に渡す。
- 直ると、手順 4 の `forget` の後の 2 回目、ペアリングの間の 3 回（`add`・`set_map`・`set_text`）は、入力が止まった後の 1 回にまとまるはず。

### 2. 入力の最中の保存で `LAT` が 3 ms を超えた

| 秒 | `LAT` 最大 | その秒の保存 |
| --- | --- | --- |
| 00:58:09 | 6.30 ms | `forget, forced`（9.2 ms）＋ `forget`（13.8 ms） |
| 00:58:25 | 6.36 ms | `set_map`（34.4 ms） |
| 00:58:26 | 14.70 ms（`<=16` に 1 件） | `set_text`（10.3 ms）。新しいペアリングの鍵の保存（NimBLE）も同じころ（推測） |

- 1 が直れば、`forget` の強制の 1 回を除き、入力と重ならなくなるはず。
- 00:56:52 の `set_alias`（9.5 ms）は入力の最中だったが、`LAT` は 2.47 ms で済んだ。重なり方で遅れが変わると見ている。

### 3. `forget` で保存が 2 回続く

- `why=forget, forced` の 2 ms 後に、同じ `why=forget` の保存がもう 1 回あった。強制の保存のあとに、もう一度 dirty が立っているように見える（推測）。
