# M1 A1 の報告：`orbit-m1-3662016-A1-usb-only.bin`（2026-09-27）

利用者の PC（Windows 11）と初代 M5Dial で確かめた。PC 側の USB の見え方は PowerShell（`Win32_PnPEntity`）で確認した。

## 結論

- **A1（書き込みモードに戻れる）は合格。** ただし **PC 本体のポートに直接つないだときだけ**。USB ハブ経由では、ボタン＋RST のあと PC が「Device Descriptor Request Failed」で認識できなかった（2 回）。
- USB の複合機器（HID 0：キーボード・マウス・コンシューマー、HID 1：設定用の Vendor 0xFF00、CDC）としての認識は正常。VID 0xCAFE / PID 0xBAF2。
- **ログ用の CDC には 1 行も出ていない。** 起動の約 1 秒後に PC 側がポートを開いていても、DTR/RTS を立てていても、8 秒間で 0 バイト。この版は CDC に書いていないか、書く前に捨てられている。
- RST だけの再起動は、USB が約 1 秒でつながり直す（PC 本体のポート、ハブ経由とも 1 回ずつ確認）。
- 画面：`ORBIT M1 3662016` / `USB --` または `USB OK` / `HEAP 210K MIN 205K`。ボタン＋RST で `Download mode` の表示が出る。

## 直してほしいこと・確かめてほしいこと

1. **CDC のログが出ない。** 何を、どの条件で（`tud_cdc_connected()` を待つか、DTR の有無）書いているかを確かめる。PC 側はポートを開いてから DTR/RTS を立てている。`START` 行だけでなく、依頼書 4.6 の `SUM` 行（1 秒ごと）を出してほしい。CDC がつながる前の出力は捨てられるので、`START` 行は CDC がつながった時点でもう一度出すとよい。
2. **USB ハブ経由で、ボタン＋RST のあと書き込みモードの USB が答えない。** M5Dial 側で直せるか（書き込みモードへ移る前に USB を切る＝`tud_disconnect()` や PHY の解放をしてから、少し待って再起動する）を検討してほしい。PC 本体のポートでは問題ないので、優先度は中。
3. 15:11 の「認識されず」（RST だけ、ハブ経由）は再現していない。2 と同じ原因の可能性がある。

## 変わらないこと

- 空きメモリは起動直後で 210 KB、最小 205 KB（画面の表示から。BLE も本家コアもまだ動いていない版なので、A9 の判定には使えない）。
- 設定ツールからの「Reset to bootloader」（4.1 の方法 1）は未確認（設定ツールの試験 A3・A4 と一緒に行う）。
