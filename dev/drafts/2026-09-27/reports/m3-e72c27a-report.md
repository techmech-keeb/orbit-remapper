## 直してほしいこと

### 1. 2 台とも 7.5 ms で大きく使うと、3 ms を少し超える秒が増える（最重要）

| | 180° | 0° |
| --- | --- | --- |
| 2 台を同時に大きく使った秒（IST 100 件/秒超・MD600 5 件/秒超） | 58 | 44 |
| 3 ms 超の秒 | 9 | 5 |
| その秒の入力 | IST 114〜130、MD600 10〜32 件/秒 | IST 94〜129、MD600 0〜31 件/秒 |

- 3 ms 超の秒はどれも、保存・命令・接続のできごとが無い秒。0° の 2 回は MD600 が止まっていて IST だけ（94〜129 件/秒）。
- 割合が向きでほぼ変わらず、状態の行の間隔も 1.006 秒（画面の無い版と同じ）なので、画面の描画ではなく、入力の多さ（受け取りか HID の組み立ての処理）だと見ている（推測）。2a の `302af13` でも、IST を大きく動かし続けた秒に 3.06〜3.29 ms が出ていた。
- 確かめ方の案：画面の無い版（`4903ae1`）で IST と MD600 を同じ使い方で 3 分。同じように出るなら画面とは無関係。
- 直し方の案：受け取りから USB への経路の重い処理（記録・集計など）を見直す。あるいは、基準を「2 台とも 7.5 ms で大きく使う場合は 3 ms 超が 1 分に N 回まで」と分けるか、利用者と相談する。

### 2. 機器側に古い鍵が残っているとき、ペアリングの探索中に切断とつなぎ直しを繰り返す（小さい）

- MD600 が古い鍵で M5 だけに向けてつなぎ直しに来る（`adv_type=1`）と、毎回 `security done status=0x5` → `stored key failed status=0x505, pairing again (pairing mode)` → `pairing start failed rc=0x6, reconnecting` → 切断、となり、0.5 秒おきに繰り返した（23:33:39〜 9 回、23:47:49〜 7 回）。M5 には鍵が無い（`no stored peer keys`）のに「保存した鍵が通らなかった」の経路に入っている。
- 機器側でペアリングし直す（MD600 の再起動 → ペアリングモード）と、新しいアドレスでふつうにつながった。実害は無い。
- `rc=0x6` で M5 からのペアリングの開始が毎回失敗する理由を確かめてほしい。鍵が無い相手のときは、この経路に入らない（または繰り返しを数回でやめる）とよい。
- 23:33:46 に MD600 の別のアドレス（`..:23:92`）が `security done status=0x0` の後に `stored key failed status=0x213` → 切断になった。機器側から切られたのか、M5 の扱いなのかは分からない。

### 3. 下の行の末尾が円の縁にかかる（ごく小さい）

- 180° のとき、`USB mounted e72c27a` の末尾の `a` が円の縁にかかって見えた（写真）。0°・90° では収まっていた。

## 気づいたこと

- 利用者は、機器の置き方の都合で、今後の試験を 180° で行いたい。
- MD600 の Bluetooth の名前は `MISTEL-1`（製造元 `ChengYong Made`、型番 `CY_BT_BRIDGE`、vid `04d9` pid `2513`）。ポート 2（Cube Turner）を空けたまま、ポート 3 に入った。台帳の決まりどおり。
- IST は起動時に自分から `lat=44 to=216` を求めて受け入れている（カードの `L44`）。前の版から同じ。
- `Screen off` は `30 s → 2 min → 10 min → never` の順に回る。
