## 新しく分かった問題

### A. BLE ホストのリセット後、ペアリング済みの機器を探せない（最重要）

- 01:24:17 のリセット後、`scan start (bonded devices only)` は出るが、その後 **MD600（ペアリング済み、`ef:64`）が 30 秒の待ちが明けても（01:24:51〜）3 分以上見つからない**。MD600 のキーを押しても同じ（01:26）。
- **Pair new device（01:27:30）で探し直した瞬間に、MD600 も meteorite40 も見つかった。**
- その後も同じ：MD600 が 30 秒避けられた（01:27:31）あと、待ちが明けても（01:28:01〜）**1 時間以上見つからない**（キーを押しても同じ。02:30 時点で `conn=0/2 scan=1`）。
- 見立て（推測）：リセット後、または「30 秒避ける」の解除後に、探索の条件（ペアリング済みのアドレスの一覧）が探索に反映されていない。**Pair new device で探し直すと直る**ので、避ける期間が明けたとき・リセット後に、探索をやり直す処理が要る。
- これが直らないと、問題 1 から自動で復旧しても、結局ペアリング済みの機器がつながらない。

### B. 別の機器のペアリング処理と重なると、正しい鍵の機器が `security start failed` で 30 秒避けられる（2 回）

- 01:24:21：リセット後、meteorite40（鍵なし）の接続処理中に MD600 がつながり、0.001 秒で `security start failed` → 30 秒避ける。
- 01:27:31：Pair new device 後、meteorite40 のペアリング中（0.3 秒違い）に MD600 がつながり、同じく失敗。
- 2 回とも MD600 は正しい鍵を持っていた（その前後で普通に暗号化できている）。NimBLE が同時に 1 つの暗号化処理しか持てない、または資源不足（`rc=0x6` 系）と見ている（推測）。**「始められなかった」は機器のせいではないので、30 秒避ける対象から外し、少し待ってやり直す**のがよい。

### C. 鍵を消した機器が黙っていると、切るまで 30 秒かかる

- 01:23:51 接続 → 暗号化の返事がない → 5 秒で `no encryption after 5 s, discovering anyway`（Report Map の読み出しは暗号化不足で失敗するはず）→ **30 秒後に `encryption failed status=0xd`** → 切断。
- 「5 秒たっても暗号化されない」時点で切るか、ペアリング待ちでないなら暗号化を待たずに切る、でよい。`press Pair new device` の経路は、機器が明示的にペアリングを求めてきたときだけ通るようで、今回の meteorite40 はその経路に入らなかった。

### D. BLE ホストのリセットで、正常だった接続も切れる

- 01:24:17 のリセットで、正常に動いていた MD600 も切れた（`reason=0xd`）。復旧のためのリセットなので許容できるが、A が直っていないと、切れた機器が戻らない。

### E. 途中までしか読めなかった Report Map を本家コアに渡している（小）

- 01:12:25：Report Map の読み出し中に相手の電源が切れ、`report map read failed status=0x7` のあと `report map 88 byte(s)`（本当は 198）→ `descriptor parsed len=88`。直後に切断処理が走るので実害は見えなかったが、失敗した記述子は渡さないほうが安全。

### F. `cancel rc=0x2` が毎秒くり返す（小）

- 15 秒の取り消しが `rc=0x2` で失敗し、25 秒まで毎秒同じ行が出る。1 回失敗したら、以後は出さなくてよい。

## 変わらないこと

- **この版の試験は USB ハブ経由だった**（報告の後で利用者が知らせた）。ここに書いた結果は、すべてハブ経由のもの。M5Dial の RST と再起動は、ハブ経由でも問題なかった。`3662016` で見つかった「ボタン＋RST のあと書き込みモードの USB が答えない」は、ボタン＋RST を使っていないので未確認のまま。
- A5（BIOS）、A6（PC のスリープ解除）は未確認。
- 機器側の古い鍵を消す操作：MD600 はリセット（アドレスが変わる）、meteorite40 は BT クリア（M5Dial の接続先を選んでから）。
