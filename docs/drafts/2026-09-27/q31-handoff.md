# セッション引き継ぎ：Q31 実験（M5Dial で BLE 機器 2 台を 7.5 ms で受けられるか）

このメモを最初に読んでから作業する。会話は日本語、平易な表現で、結論を先に書く。

## 何をしているか

- リポジトリ：`techmech-keeb/orbit-remapper`（private、将来 OSS 公開前提）。
- 試験プログラムは、ブランチ `claude/laughing-volta-r6lpn4` の `experiments/q31-s3-two-ble/` にある（ESP-IDF v5.5.5 と NimBLE）。PR はまだ作っていない。
- 仕様は `docs/drafts/2026-09-26/q31-experiment-brief.md`、使い方とログの読み方は `experiments/q31-s3-two-ble/README.md` を読む。
- 目的：初代 M5Dial が BLE のキーボード・マウス 2 台を、どちらも 7.5 ms で 10 分以上安定して受けられるかを確かめる。受けられれば D 案（M5Dial 単体）、受けられなければ E 案（XIAO nRF52840 Plus＋M5Dial）。
- このプログラムは受けた報告を数えるだけで、PC へ入力は送らない。Dial につながった機器は、PC では反応しなくて正しい。

## この PC のセッションにやってほしいこと

1. M5Dial（USB-C で PC に接続。USB の仮想シリアル）のシリアルログを直接取る。`Q31` で始まる行だけを使う。速度の設定は関係ない。
   - ブラウザの書き込みページの Console など、ほかのアプリがポートを開いているとつながらない。先に閉じる。
   - ログはファイルに残す。
2. ファームの版を確かめる。1 行目の `Q31 START ... app=<コミット>` が `60540d8` であること。違えば書き込み直す。
   - 書き込み用のファイルは、利用者が受け取った `q31-60540d8-at-connect.bin`。`esptool.py --chip esp32s3 -p <ポート> write_flash 0x0 <ファイル>` で書き込む（アドレスは 0x0）。T7 のときだけ `q31-60540d8-after-connect-T7.bin` を使う。
   - ESP-IDF がこの PC にあれば、ブランチからビルドしてもよい（手順は README）。
3. ログから判定して、利用者に次の操作（機器を動かす、電源を入れ直すなど）を短く指示する。T1〜T7 の手順は依頼書 §4 と README にある。

## ここまでに分かったこと（2026-09-27、画面の写真から。ログはまだ見ていない）

| 表示 | 機器 | 結果 |
| --- | --- | --- |
| 下位アドレス `C9C6` | Mistel MD600 Alpha（キーボード） | 7.50 ms・latency 0・暗号化済み・通知 4 つ登録（`S4`）。S キー 1 回で報告 2 回（押す・離す）が届いた |
| 下位アドレス `E4F9` | meteorite40（トラックボール付きキーボード。ZMK と推測、要確認） | 版 `b56cd99` では 15.00 ms・latency 30 になった。暗号化済み、`S3` |

- 2 台同時に接続できている。前の版では 2 台とも 7.50 ms の接続が約 23 分続いた（報告は届いていなかった）。
- meteorite40 の 15 ms は、ESP32-S3 に断られたのではなく、meteorite40 が接続後に「7.5〜15 ms、latency 30」（ZMK の既定値と推測）を求め、それを受けた NimBLE が 15 ms を選んだと見ている。**推測で、ログの `update req` の行で要確認。**
- 版 `60540d8` では、機器の範囲に 7.5 ms が入っていれば 1 回だけ 7.5 ms を求め直す（`asking for it again`）。これが通るか、HCI 0x12 などで断られるかを見る。断られた場合は、先例（prior-art.md §4.33）と同じ結果になる。
- meteorite40 は PC でも動いていた。USB で PC につながっているか、PC 用の接続先が選ばれていると、入力は PC に行き、Dial では報告が 0 になる。測るときは USB を抜くか、Dial 用の接続先に切り替える。
- D0・D1 の番号は、つながった順に付く。起動のたびに入れ替わることがある。

## 次に確かめること

1. `60540d8` で、meteorite40 が 7.50 ms になるか（`EVT` の `update req`、`asking for it again`、`updated`、`update failed` の行）。
2. 2 台とも 7.5 ms で、同時に動かしたときの `DEV` 行の `rpt`・`maxgap`・`gaps<=8/16/32/>32`（T3、T4）。
3. その状態で 10 分以上、切断や間隔の変化がないか（T5）。電源の入れ直し・スリープからの復帰（T6）。T7。
