## 構成の決定（2026-09-26 ユーザー決定）

| ID | 決定 | 影響 |
| --- | --- | --- |
| H1 | 表示と操作は M5Dial を使う（丸型 TFT、タッチ、内蔵ダイヤルとボタン） | R02（透過表示）を取り下げ。E1 の Glass2 を収める筐体は流用できず、M5Dial 用の筐体を新たに設計する。E1 の CAD は経緯として残す |
| H2 | Pico を省く。M5Dial 内の ESP32-S3 が USB ホストと UI を担い、XIAO nRF52840 が BLE 入力・リマップ・PC への USB 出力を担う（architecture の C 案） | Pico B との UART（Q22）は不要になる。S3 の USB ホストのファームは新規。F1-2（外付けハブで複数台）は ESP-IDF の USB ホストのハブ対応に依存する（Q23） |

選んだ理由（会話での検討）：Pico B を使うには本家の dual B ファームの改造と 4 本の配線が必要で（Q22）、「無改造で流用」の利点が薄れていた。S3 に移せば、XIAO との通信方式を自由に選べ、画面とダイヤルの処理を XIAO から外せる。本体の画面でできることが多い（F3）ため、丸型カラー画面とタッチの M5Dial が向く。



本家 HID Remapper の機能（[機能境界](hid-remapper-capabilities.md)、master `51ab8b3` で再確認）を踏まえ、ユーザーが選択肢から決めた事項です。**実装・実機検証はまだありません。** 「本家との差」は、本家に無く Orbit で新しく作る必要がある部分です。

### F1 入力機器

| ID | 決定 | 本家との差 |
| --- | --- | --- |
| F1-1 | 対象はキーボード、マウス・トラックボール、ゲームパッド。MIDI は対象外 | ゲームパッドの機種別補正（quirks）は BLE 版では効かない（VID/PID を 1/1 で渡すため） |
| F1-2 | **最初の版（2026-09-26 改定）**：USB 側は M5Dial のポートに直結した 1 台を保証する（ロースピードの機器を含む）。外付けハブ経由の複数台は保証せず、動けば使える扱いにする（試験的）。ハブで複数台を保証する対応は後の版で広げる。当初の決定（外付けのセルフパワーハブで複数台）は後の版の目標として残す | ESP32-S3 のホストチャネルは 8 つで、ハブ越しは 3〜5 台程度の見込み。ロースピード機器がハブ越しで動かない可能性もある（open-questions「Q23 ESP-IDF のハブ対応」）。直結 1 台なら両方の懸念を避けられる |
| F1-3 | BLE 側は本家の設定どおり同時接続 8 台まで | 設定上の上限であり、安定動作する台数は実測が必要 |
| F1-4 | 機器ごとの設定番号は USB を 1〜7、BLE を 8〜15 に分ける。0 は全機器。最初の版で保証する USB 機器は 1 台だが、番号の割り当ては後の版のために変えない。**ただし M5Dial 構成では、ESP32-S3 のホストチャネル数（8）により、同時に使える USB 機器は 3〜5 台程度の見込み**（open-questions「Q23 ESP-IDF のハブ対応」） | 本家のコアは USB のハブポートと BLE の機器番号を同じ 4 ビットの欄で扱う。BLE 機器にペアリング順ではなく安定した番号を割り当てる仕組みが必要 |

### F2 複数機器の同時利用

| ID | 決定 | 本家との差 |
| --- | --- | --- |
| F2-1 | 別の機器で押したキーは組み合わせる（例：BLE キーボードの Ctrl＋USB マウスのクリック） | 本家と同じ |
| F2-2 | レイヤーは機器ごとに独立させる | 本家はレイヤー状態を本体全体で 1 つだけ持つ（`remapper.cc` の `layer_state_mask`）。機器ごとに持つようコアを変更する。全機器（0 番）向けの設定を、どの機器からの入力かを保ったまま評価する作り変えが必要 |
| F2-3 | レイヤーは機器のレイヤーキーと本体のダイヤルの両方で切り替える。レイヤーキーは押した機器に効く | 本体のダイヤル操作は新規 |
| F2-4 | ある機器のキーで、別の機器のレイヤーを切り替えられるようにする | 本家の設定にある「出力先の番号」欄（`hub_ports` の上位 4 ビット）を流用できる見込み（未検証） |
| F2-5 | 押したまま機器が切れたときは、その機器の入力だけを解除する。他の機器の入力とレイヤーは維持する | 本家には切断時に押下状態を解除する処理が見当たらない（`remapper.cc` の `device_disconnected_callback`）。入力を機器ごとに記録する実装が必要 |

### F6 合流とパススルーの選択

> **2026-09-26 見送り（下記「利用場面の検討」で再判断）。** 選ばれた利用場面に、F6 でしか解決できないものがなかったため、最初の版の要件から外した。検討の記録として以下を残す。


目的は「PC 側で機器を別々に認識させる」こと（ユーザー回答）。本家の「Unmapped inputs passthrough」（割り当てのない入力を、合流した仮想機器からそのまま出す機能）とは別物です。

| ID | 決定 | 本家との差 |
| --- | --- | --- |
| F6-1 | 機器ごと（設定番号の単位）に「合流」か「パススルー」かを選ぶ。選択は設定セットに含め、設定セットを切り替えると選択も切り替わる | 新規 |
| F6-2 | パススルーした機器は、PC から別の HID 機器として見せる。報告の形式には、その機器自身のレポート記述子を使う | 本家の XIAO 版は、PC へ出す HID の窓口が 2 つ（合流した仮想機器と設定ツール用）で固定（`firmware-bluetooth/src/main.cc` の `HID_0` / `HID_1`）。窓口を動的に追加する実装が必要 |

制約（ソースと USB の仕様からの判断。**未検証**）:

- パススルーできる台数には上限がある。nRF52840 の割り込み転送用の口（エンドポイント）は限られ、既に 2 つ使っているため、残りは 5 つ前後の見込み。複合キーボードは 1 台で複数消費する（要確認）。
- パススルー機器の増減や設定セットの切替のたびに、本体を PC へ接続し直させる必要がある。その間は合流側の入力も途切れる。
- PC から見える VID/PID は Orbit のものになる。メーカーの専用ソフトや独自通信を使う機能は使えない。HID でない機器（XInput のゲームパッドなど）は通せない。
- パススルー機器の入力は合流側に入らないため、リマップ・レイヤー・同時押しの組み合わせ（F2）の対象外になる。LED の送り返し（F5）は、パススルー機器でも中継する。
- Windows・macOS は、複数のキーボードやマウスを通常 1 つの入力として扱う。機器を区別できるのは、機器ごとの入力を読むアプリ（Raw Input を使うゲームなど）に限られる。
- USB 側の高速な機器（1000 Hz のマウスなど）が Pico B → UART 経由で遅れないかは実測が必要。

### 利用場面の検討（2026-09-26）

パススルーや Vial が本当に必要かを、利用場面ごとに検討した。接続方法は次の4つ。

| 方法 | PC からの見え方 | リマップ |
| --- | --- | --- |
| 合流（F1〜F5） | Orbit 1 台 | 効く |
| HID パススルー（F6） | Orbit の中の別々の機器（VID/PID は Orbit のもの） | 効かない |
| ハブ直結（内蔵ハブ IC で PC と直接つなぐ） | 機器そのもの | 効かない |
| 挿し替え（Orbit を通さず PC に直接つなぐ） | 機器そのもの | 効かない |

| # | 場面 | 解決できる方法 | ユーザーの判断 |
| --- | --- | --- | --- |
| S1〜S5 | 普段の入力（配列変更、マウスの割り当て、左手デバイスとの組み合わせ、ゲームパッド変換、BLE キーボードを BIOS・KVM で使う） | 合流 | 前提 |
| S6 | ゲームパッド 2 台で 2 人プレイ | HID パススルー、ハブ直結、仮想ゲームパッドを複数出す（Q20） | 起こらない |
| S7 | 機器ごとに動きを変える PC 側ソフト（Karabiner-Elements など。VID/PID で区別することが多い） | ハブ直結、挿し替え | 起こる |
| S8 | 専用ドライバーが必要な機器（ペンタブレット、3D マウス） | ハブ直結、挿し替え | 起こる |
| S9 | Vial・VIA・Remap で自作キーボードの配置を変える | ハブ直結、挿し替え（HID パススルーは Vial デスクトップ版のみ、工夫が必要） | 挿し替えで対応 |
| S10 | キーボードのファーム更新（UF2・DFU） | ハブ直結、挿し替え | 挿し替えで対応 |
| S11 | メーカー専用ソフトでの設定 | ハブ直結、挿し替え | 挿し替えで対応 |
| S12 | 自作キーボードの開発（書き込みと Vial の往復） | ハブ直結、挿し替え | 挿し替えで対応 |
| S13 | USB メモリなど HID 以外の機器を挿す | ハブ直結、挿し替え | 起こらない |

**決定（2026-09-26）**

| ID | 決定 |
| --- | --- |
| U1 | 最初の版は合流（F1〜F5）だけを持つ。F6（HID パススルー）は見送る |

## 元BOMと設計資料の差分

元BOMは変更せず保存しています。少なくとも次の差分が残ります。

- PCB約60×45 mm → E1機械配置74×58 mm。
- Glass2給電3.3 Vの記載 → 設計時に5 V給電・3.3 Vロジックを前提へ変更。回路確認が必要。
- 純正PicoのコネクタはMicro USB。BOM中のUSB-C表記を引き継がない。
- 外部リセットSW4、締結部材、パッド、短尺ハーネス等を追加する案。
- Glass2の53×42×6 mm表記と機械図からのモデル寸法の差は未解決。
- M5Dial案ではPico・Glass2・個別操作部の変更候補が生じるが、削除・置換をBOMへ確定反映していない。
