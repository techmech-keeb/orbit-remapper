# 構成の分岐と技術的な未確定事項

## A: E1 / Glass2 / Pico — 既存機構試作案

| 部品 | 元BOM・設計時の担当 |
| --- | --- |
| XIAO nRF52840 Plus | BLE入力、リマップ、PC向けUSB、UI制御を想定 |
| Raspberry Pi Pico | USBキーボードのホスト。dual B版ファームを無改造で利用する意図 |
| Glass2 Unit U158-B | 透過型OLED表示 |
| 個別エンコーダー・ボタン | 操作と追加外部リセット |

UART、電源、USB線の空間を予約した機械設計です。XIAO側のUART受信・BLEとの共存や、元BOM全体の動作が確認済みという意味ではありません。

## B: M5DialをUIとして追加 — 検討案

XIAOを主処理、PicoをUSBホスト、M5Dial内のS3をUIとする三マイコン案。Pico側の既存ファーム流用を優先する選択肢です。部品・配線は増え、XIAOとUI間の通信実装は依然必要です。

## C: M5Dial内のS3がUIとUSBホストを兼任 — 有力な検討案

| 部品 | 担当の提案 |
| --- | --- |
| M5DialのESP32-S3 | USBキーボード読取、画面、ダイヤル・タッチ操作 |
| XIAO nRF52840 Plus | BLE入力、リマップ、PC向けUSB出力 |
| UART | キー入力、接続状態、設定操作、表示用状態の転送 |
| Pico | 機能をS3へ実装できた場合に削除可能 |

ESP32-S3のUSB OTGをホストとして使い、PC向けUSBデバイスをXIAOへ分担する構成です。S3の画面はSPIなのでUSBとは別ですが、UIとホストの同時動作を検証する必要があります。Pico用UF2の単純な載せ替えはできません。

### ハードウェアで詰めること

- ESP32-S3内蔵PHYのUSB信号はD− GPIO19 / D+ GPIO20。実際のM5Dial基板・リビジョンでの取り出し方を確認する。
- Groveの一般GPIOポートを、そのまま内蔵USBの端子と扱わない。
- 背面USB-Aへキーボード用5 Vを供給する経路、電流制限、突入・逆流防止、ESDを設計する。
- M5DialのUSB-Cへのアダプター追加だけでホスト給電が成立すると断定しない。
- USBホスト利用中のファーム書き込み・デバッグ、リセットとブートのアクセスを計画する。
- S3のUSB Serial/JTAGは汎用HIDデバイス用の二つ目のUSB OTGではない。

### ファームウェアで詰めること

- USB HID入力、ディスクリプタ、接続・切断、必要な出力レポートの扱い。
- XIAO側が実際に受け付けるUART仕様の調査と追加実装。Pico dual B互換を維持するか、新規仕様にするか未決定。
- 基本キーだけでなく、同時押し、メディアキー、複合デバイス、必要に応じハブ・LED制御の対象範囲。
- UI処理とUSB処理を分離し、画面更新で入力処理が止まらないタスク・キュー構成。
- XIAO側のBLE入力とUART入力の同居、設定の所有者、再接続・再起動時の状態同期。

## M5Dialという製品の扱い

ユーザーの表記は「S3StampDial」。検討ではM5Dialを想定しましたが、初代かV1.1かは未確定です。調査参照したV1.1はStamp-S3A、1.28インチ240×240丸型TFT、外形51×51×32.3 mm。これはE1の寸法ではなく、部品選択の参考情報です。[メーカー資料](sources.md#技術資料)

M5DialのTFTは透過表示ではないため、初期の「向こうが透ける」要件をそのまま満たしません。UI分岐の採用時に、透過性を残すか、要件を変更するかを決める必要があります。Picoを省いてもM5Dialの厚みがあるため、筐体の小型化は未保証です。

## 最初の検証手順（提案）

1. 対象部品とリビジョン、XIAO側のコードを確認する。
2. S3でUSBキーボードを読み取る。
3. UARTでXIAOへ渡し、PCに入力を出す。
4. UI操作・画面更新を並行させ、入力と再接続を確認する。
5. 必要なBLE併用と電流予算を確認する。
6. 成立した部品・端子・保守条件に合わせてPCB配置と筐体を設計する。

ここに実装済みファームや合格結果はありません。E1のCADをM5Dial用と読み替えないでください。
