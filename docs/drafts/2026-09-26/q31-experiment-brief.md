# Q31 実験の依頼書：M5Dial で BLE 機器 2 台を 7.5 ms で受けられるか

別の AI（または人）に試験用プログラムを作ってもらうための依頼書。背景は [handoff.md](handoff.md)、根拠は [prior-art.md](prior-art.md) の「esp32-hid-gamepad-bridge」と「何台まで 7.5 ms の実績があるか」を読む。

## 1. 目的

初代 M5Dial（ESP32-S3）が、BLE のキーボードとマウスの 2 台を、**どちらも接続間隔 7.5 ms で、安定して**受けられるかを確かめる。

結果で構成を決める（ユーザー決定、2026-09-26）。

| 結果 | 判断 |
| --- | --- |
| 2 台とも 7.5 ms で、10 分以上切れずに動く | D 案（M5Dial 1 台で作る）に切り替える |
| 15 ms 以上に落ちる、断られる、切断や入力の欠けが起きる | E 案（XIAO nRF52840 Plus＋M5Dial）のまま進める |

**作るのは測定用の試験プログラムだけ。** リマップ、PC への USB 出力、設定画面は作らない。

## 2. 使う機材

| 機材 | 内容 |
| --- | --- |
| 初代 M5Dial | M5StampS3（ESP32-S3FN8、PSRAM なし）搭載。技適 219-229318。書き込みとログは本体の USB-C |
| BLE キーボード 1 台、BLE マウス 1 台 | ユーザーの手持ち。型番は結果の記録に書く |
| PC | 書き込みとログの取得だけに使う。M5Dial と PC の間に BLE 接続はない |

## 3. 試験プログラムの仕様

### 必須

1. **ESP-IDF と NimBLE を使う**（Arduino ではなく）。ESP-IDF の版は結果に記録する。
2. **Wi-Fi は使わない**（初期化しない）。
3. BLE の親（セントラル）として、HID 機器（HOGP、サービス 0x1812）を探して最大 2 台つなぐ。
4. **接続を始める時点で間隔 7.5 ms（単位 1.25 ms で 6）を指定する。** 例：`ble_gap_connect()` の接続条件で `itvl_min = itvl_max = 6`、latency 0、supervision timeout は 4 秒程度。
   - つないだ後に短くする要求（`ble_gap_update_params()`）は、先行例で 15 ms より短いと断られている（prior-art.md §4.33）。今回はまず接続時の指定で試す。
   - 比較のため、接続後の要求で 7.5 ms を求める方式も、設定で切り替えて試せるようにする。
5. 暗号化（ペアリング）を自分から始める。HID 機器は暗号化しないと入力を送らないことがある（prior-art.md §4.29）。ペアリング情報は保存し、再起動後に再接続できるようにする。
6. 入力の報告（Report、0x2A4D）の通知を受ける。中身の解析は不要で、**届いた回数と時刻だけ**を数える。
7. 2 台つないだら、探すこと（スキャン）を止める。
8. 次を USB のシリアルに 1 秒ごとに出す。画面にも同じ要点を出す（丸い 240×240 の画面。見やすさは問わない）。
   - 機器ごと：接続の番号、相手のアドレス（下位だけでよい）、**実際の接続間隔**（`ble_gap_conn_find()` などで得た値）、latency、timeout
   - 機器ごと：直近 1 秒の報告数、報告の間隔の最大値
   - 接続条件が変わったとき（`BLE_GAP_EVENT_CONN_UPDATE`）、相手から変更を求められたとき（`BLE_GAP_EVENT_CONN_UPDATE_REQ`）、切断（理由のコード付き）、断られたとき（HCI のエラーコード付き）
9. 切断されたら、自動で再接続を試みる。

### 使わないもの・気をつけること

- ESP-IDF の `esp_hidh`（BLE HID ホスト部品）は不具合が多い（prior-art.md の表）。使う場合は既知の不具合を避ける。NimBLE の GATT を直接使う方が安全。
- スリープから戻ったキーボードは HID の識別子を出さずに接続を求めることがある（§4.20）。再接続は保存したアドレスで行う。
- BTstack（bt-keyboard-remapper）のコードは流用しない（ライセンスが合わない）。

## 4. 試す手順

| 番号 | 内容 | 見ること |
| --- | --- | --- |
| T1 | マウス 1 台だけ | 7.5 ms になるか。マウスを動かし続けて 1 秒の報告数 |
| T2 | キーボード 1 台だけ | 7.5 ms になるか |
| T3 | 2 台（マウス → キーボードの順） | 両方 7.5 ms か。マウスを動かしながらキーを打って、報告の欠けや遅れがないか |
| T4 | 2 台（キーボード → マウスの順） | 順番で結果が変わるか |
| T5 | T3 の状態で 10 分以上 | 切断、間隔の変化、報告の間隔の最大値 |
| T6 | 片方の電源を切って入れ直す／機器をスリープさせて戻す | 再接続できるか。戻った後も 7.5 ms か |
| T7 | 接続後の要求で 7.5 ms を求める方式に切り替えて T3 | 先行例と同じく断られるか |

報告数の目安：7.5 ms なら 1 秒に最大約 133 回。機器自体が送る回数の上限もあるので、1 台だけのとき（T1）の値と 2 台のときの値を比べる。
